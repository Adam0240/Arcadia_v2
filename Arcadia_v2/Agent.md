# Species-Element Move Set Refactor Plan

## Goal

Refactor creature move assignment so each species has shared stats, while each species-element pair can have its own move set.

This avoids both extremes:

- Full duplicated animal entries for every elemental creature.
- One generated move set that forces every Cat variant to use the exact same four move templates forever.

The target design is:

- Species owns shared stats.
- Species + element owns the move set.
- Move templates are reusable across species and elements.

## Current State

- `AnimalFactory` now generates all animals from species definitions and elements.
- `AnimalSpecies` currently stores:
  - Name
  - Speed
  - Base health
  - Variants
- `AnimalVariant` currently stores:
  - Element
  - Concrete `Move` list
- Cat variants are generated by `CreateCatVariants()`.
- The Cat move generation reuses `MoveData` templates such as `Fury`, `SpeedAttack`, `DefensiveMove`, and `Bomb`.
- Most other species still use legacy concrete move arrays through `CreateVariants(...)`.

## Design Problem

The current Cat implementation proves reusable themed moves work, but it is too rigid as a final pattern.

Example:

- `Nature Cat` may know `Nature's Fury`.
- `Mystic Cat` may know `Mystic Fury`.
- Those moves share the same template and power.

But species of the same element may also need shared elemental moves:

- `Nature Lion` may know `Nature's Storm`.
- `Nature Wolf` may also know `Nature's Storm`.

So the move set needs to be defined per species-element pair, while still reusing shared move templates.

## Files Affected

### `Arcadia_v2/Creatures/Move.cs`

This file should own reusable move concepts:

- `MoveTemplate`
- Shared move templates such as `Fury`, `Bomb`, `Storm`, etc.
- `MoveData.CreateElementMove(...)`
- `MoveData.CreateNeutralMove(...)`
- Element-to-`MoveType` mapping
- Element name grammar such as `Nature's Fury`

This file should not know which animals get which moves.

### `Arcadia_v2/Creatures/AnimalFactory.cs`

This file should own creature roster construction:

- Species stats
- Species-element move set assignment
- Conversion from move-set definitions into concrete `AnimalVariant` values

This file should not define reusable move templates or move naming/type rules.

### `UnitTest/AnimalTest.cs`

Factory tests should be updated or added to verify:

- Species variants share stats.
- A species can have different move sets per element.
- Two different species can share the same element move template.
- The generated move names and powers are correct.

### Possibly Affected Later

These files should not need structural changes for this refactor, but tests may touch them indirectly:

- `Arcadia_v2/Battles/BattleHelpers.cs`
- `Arcadia_v2/Battles/BattleEngine.cs`
- `Arcadia_v2/Gameplay/WildBattleFlow.cs`

They already consume concrete `Move` objects, so they should not care whether a move came from a template or from a static legacy `MoveData` field.

## Proposed Types

Keep `MoveTemplate` in `Move.cs`.

Add a small move slot type in `AnimalFactory` because this describes how a species uses a move template.

```csharp
private sealed record MoveSlot(
    MoveTemplate Template,
    bool IsElemental);
```

Use helper methods for readability.

```csharp
private static MoveSlot Elemental(MoveTemplate template)
{
    return new MoveSlot(template, IsElemental: true);
}

private static MoveSlot Neutral(MoveTemplate template)
{
    return new MoveSlot(template, IsElemental: false);
}
```

Then convert slots to concrete moves when creating an `AnimalVariant`.

```csharp
private static Move CreateMove(AnimalElement element, MoveSlot slot)
{
    return slot.IsElemental
        ? MoveData.CreateElementMove(element, slot.Template)
        : MoveData.CreateNeutralMove(slot.Template);
}
```

## Proposed Species Shape

Update `AnimalSpecies` so it stores move sets by element instead of already-built variants.

```csharp
private sealed record AnimalSpecies(
    string Name,
    int Speed,
    int BaseHealth,
    IReadOnlyDictionary<AnimalElement, IReadOnlyList<MoveSlot>> MoveSets);
```

Then `AnimalFactory` can build variants from the move sets.

```csharp
private static AnimalVariant CreateVariant(
    AnimalElement element,
    IReadOnlyList<MoveSlot> moveSlots)
{
    return new AnimalVariant(
        element,
        moveSlots.Select(slot => CreateMove(element, slot)).ToArray());
}
```

## Example Move Templates

Add reusable templates in `MoveData`.

```csharp
public static readonly MoveTemplate Fury = new("Fury", 10);
public static readonly MoveTemplate Storm = new("Storm", 10);
public static readonly MoveTemplate SpeedAttack = new("Speed Attack", 5);
public static readonly MoveTemplate DefensiveMove = new("Defensive Move", 1);
public static readonly MoveTemplate Bomb = new("Bomb", 12);
public static readonly MoveTemplate Roar = new("Roar", 8);
public static readonly MoveTemplate Howl = new("Howl", 8);
```

## Example Move Sets

Cat can reuse Fury and Bomb across elements.

```csharp
[AnimalElement.Nature] = new[]
{
    Elemental(MoveData.Fury),
    Neutral(MoveData.SpeedAttack),
    Neutral(MoveData.DefensiveMove),
    Elemental(MoveData.Bomb)
}
```

Lion and Wolf can share Storm for their Nature variants.

```csharp
[AnimalElement.Nature] = new[]
{
    Elemental(MoveData.Storm),
    Neutral(MoveData.SpeedAttack),
    Neutral(MoveData.DefensiveMove),
    Elemental(MoveData.Roar)
}
```

```csharp
[AnimalElement.Nature] = new[]
{
    Elemental(MoveData.Storm),
    Neutral(MoveData.SpeedAttack),
    Neutral(MoveData.DefensiveMove),
    Elemental(MoveData.Howl)
}
```

Generated output:

- `Nature Lion` gets `Nature's Storm`.
- `Nature Wolf` gets `Nature's Storm`.
- Both share power/type/name generation through the same `Storm` template.

## Implementation Steps

1. Add any missing reusable move templates to `MoveData`, such as `Storm`, `Roar`, and `Howl`.
2. Add `MoveSlot`, `Elemental(...)`, and `Neutral(...)` helpers inside `AnimalFactory`.
3. Change `AnimalSpecies` to store `MoveSets` instead of prebuilt `Variants`.
4. Add helper methods that build `AnimalVariant` from a species, an element, and that element's move slots.
5. Convert Cat first using explicit species-element move sets.
6. Convert Lion and Wolf next to prove cross-species sharing with `Nature's Storm`.
7. Keep legacy concrete move arrays for the remaining species until they are intentionally converted.
8. Run tests after each conversion.
9. Update `AnimalTest` to verify:
   - `Nature Cat` has `Nature's Fury`.
   - `Mystic Cat` has `Mystic Fury`.
   - `Nature Lion` and `Nature Wolf` both have `Nature's Storm`.
   - Shared templates keep the same power.

## Migration Notes

- Do not return to full duplicated animal entries.
- Do not put reusable move template definitions in `AnimalFactory`.
- Avoid making every element use a universal move set unless that is truly the desired design.
- Prefer explicit move sets per species-element pair when design intent matters.
- It is acceptable to keep unconverted species using the current legacy move arrays temporarily.

## Open Decisions

- Should every species-element pair be explicitly listed, or should there be a default fallback move set per species?
- Should missing element move sets throw an error, or fall back to a generic element move set during development?
- Should move names stay title case, such as `Nature's Storm`, while old legacy moves remain uppercase?
